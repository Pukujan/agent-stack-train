# Project name

> One sentence describing the human problem and the project's concrete promise.

## Start here

Name the situation a reader recognizes, then explain the consequence in plain language.

## The problem

Describe what is hard, expensive, risky, or confusing today. **Use a concrete example before introducing architecture.**

## What this project does

Explain the mechanism in a few steps. Keep implementation details available for readers who need them, but do not make them solve the story themselves.

## Evidence and boundaries

Link claims to code, tests, data, or committed artifacts. *Say what is not yet proven.*

## Try it

Give the smallest useful path to a first result.
