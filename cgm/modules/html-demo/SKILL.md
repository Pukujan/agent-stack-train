# HTML demo

## Workflow

1. Define the reader's first question and the demo's single promise.
2. Map the story to semantic sections: context, problem, mechanism, proof, next step.
3. Reuse project visual tokens rather than inventing a second brand.
4. Use semantic HTML, visible focus states, useful alt text, and keyboard-accessible controls.
5. Test mobile, tablet, and desktop widths.
6. Capture screenshots and record browser/viewport details.

## Quality bar

The demo must remain understandable without animation, hover, or a wide screen. Decorative complexity should never compete with the product explanation.
